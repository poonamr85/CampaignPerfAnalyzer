Ad Campaign Performance Dashboard Guide

A practical guide to the project objective, technology choices, data flow, user workflow, dataset, and development prompts.

1 Project overview and objective

The app helps marketers evaluate advertising performance across Facebook, Instagram, Pinterest, and Twitter. It turns a campaign CSV into a consistent view of investment, engagement, conversions, and return, helping users identify strong campaigns and areas to investigate before changing budgets.

The objective is to answer three questions: where is the budget going, which campaigns and channels deliver results, and how is performance changing over time? Four views and shared filters let users move from an overall summary to channel, campaign, and time-based analysis.

The current implementation is a Python dashboard that runs locally. Replit configuration is included for future hosting.

4 User guidance

Running the dashboard

From the project folder, run .venv/bin/streamlit run app.py, then open http://localhost:8501/. Keep the server running while using the dashboard. Installation and Replit instructions are in README.md.

How to load and explore data

  1. Prepare a CSV. Download the blank template and add campaign records, or use the sample CSV from the data folder.
  2. Select the file. Use Upload campaign CSV. The pending message means the selected file has not yet replaced the displayed data.
  3. Apply the file. Click Load Campaign Data. Valid data becomes active; invalid data shows an error and preserves the previous dataset.
  4. Confirm the source. The status strip shows the sample label or loaded filename, selected date range, matching record count, and currency.
  5. Explore. Set global filters and choose a view. Filters update all four views consistently. Loading a different dataset resets global filters.

Clearing a filter selection produces no matches. An empty result displays a clear message. Clearing the upload returns to sample data when the sample option is enabled.

The four views

Filters and data status

The sidebar provides date, channel, audience, and campaign goal filters, plus a reset button. Campaign search applies only within Campaign Details and searches the globally filtered results.

The status strip displays the selected date interval, rather than repeating the reporting period in multiple messages. When filters reduce the dataset, it shows how many records match out of the total loaded. Sample mode includes a short note identifying the data as synthetic.

Rates use aggregated totals rather than averages of row percentages. Missing revenue makes Revenue, ROI, and ROAS unavailable for the affected group. Zero denominators display N/A. The sample records explicitly use zero booked revenue for lead-generation campaigns.

Advertising ROI excludes product costs and other business expenses. Compare campaigns with consistent goals and attribution definitions. A lead, a sale, and an awareness outcome may have different business values.

5 Dataset notes

Synthetic sample data means artificially created records for demonstration and testing. The amounts look plausible but do not come from real advertising accounts and do not represent actual business performance.

The sample covers September 1–30, 2026, with 240 rows across eight campaigns and four channels, in USD. Campaign goals include Sales, Leads, Traffic, and Awareness. It provides date, campaign, audience, and goal fields for exercising the global filters.

The sample was originally created with blank revenue for the lead-generation campaign. Because the app requires complete revenue within a group to calculate return metrics, the combined Revenue and Advertising ROI showed N/A. Those synthetic records now explicitly represent zero booked revenue. Missing revenue in a real upload remains unknown and is not automatically replaced with zero.

FilePurpose
data/sample_campaign_performance.csvFilled sample that can be uploaded repeatedly or loaded automatically in sample mode.
data/campaign_template.csvHeader-only template for preparing real campaign data.

The two download buttons serve these separate purposes. Uploaded files are held in the current app session; they are not automatically saved into the data folder. The app uses supplied CSVs rather than live advertising-platform connections.

CSV requirements

Required: date, campaign_id, campaign_name, channel, audience, campaign_goal, spend, clicks, conversions, and currency.

Optional: revenue and impressions. Revenue is needed for return metrics; impressions are needed for CTR.

Each row should be an additive observation for one date, campaign, channel, audience, and goal. Use one currency per file, whole numbers for counts, and nonnegative numeric amounts. YYYY-MM-DD is the recommended date format. Twitter exports labeled X are normalized to Twitter. Avoid combining detail rows with overlapping totals.

The reusable sample contains 240 synthetic records across eight campaigns and four channels for September 1–30, 2026 in USD. The sample and blank template are maintained in data/sample_campaign_performance.csv and data/campaign_template.csv.
